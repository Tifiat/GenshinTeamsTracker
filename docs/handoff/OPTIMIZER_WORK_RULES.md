# Optimizer work rules

Read this only for GCSIM optimizer, formula capture, set effects, engine-bound
optimizer tests or disposable optimizer experiments. Architecture and gate order
belong to `GCSIM_OPTIMIZER_TRACE_EQUATION_HANDOFF.md`; installed acceptance and
the immediate next action belong to its linked current checkpoint. Read their
relevant sections, not their entire histories.

## Engine and resource boundary

- The active selected engine owns the executable, source registries and catalog
  for every optimizer/button test. Never silently substitute another installed
  engine or an updater staging tree. A future version selector changes the one
  active pointer.
- GCSIM owns gameplay coefficients and formulas. GTT observes source arithmetic,
  runtime paths and input ownership; do not hardcode Lunar/Stellar or character
  rules in the consumer. Unknown operands, ancestry, branches, tasks and schedule
  changes stay diagnosed boundaries. Zero wholly frozen hits is not complete
  dependency coverage.
- Budget engine calls separately from offline search. Do not substitute
  per-candidate GCSIM brute force for an incomplete model. If uncertainty exceeds
  the user-configured exact-finalist limit, return a labeled best-effort result
  rather than silently widening verification. Selected/All Sets have no product
  wall-clock timer; preserve cooperative Finish and emergency Cancel as distinct
  operations. Use reduced/parity gates before
  full-account or n=1000 validation.
- Disposable experiments use `tools/managed_optimizer_experiment.py` for the
  whole capture/export sequence, or an equivalent tested lifecycle. All outputs
  belong to one owned scratch scope and are cleaned on exit. Failed cleanup or
  orphan residue blocks another allocation. Export minimal durable evidence
  first; adapt legacy scripts before rerunning them.

## Formula and response invariants

- Selected/All Sets use the Go optimizer; removed Python strategies must not
  return as fallbacks. Selected fixes equipped 4p or 2+2 with one flexible piece.
  All Sets chooses packages and owned inventory with explicit incomplete-search
  reporting. The approved common-math/search replacement is described in trace
  handoff section 2; source work is not product/button acceptance.
- The neutral All Sets path captures without set rows, retains effect inputs
  after reduction and observes events independently of subscriptions. Do not
  rewrite ordinary GCSIM sets. Same hit topology is not response proof; unknown
  activation is neither zero nor full uptime. Approximate coverage may rank
  candidates but cannot certify a hard bound or response.
- Keep set effects separate from raw artifact stats. Never leave an old buff in
  place while adding a replacement. Static replacement attestations must come
  from trusted verifier output, not UI flags or a passing point witness. The
  isolated context pilot's synthetic certificates are test-only. Source amount
  alternatives and old-context increment probes are proposal features, not a
  changed-set DPS total. Bind neutral inputs to exact graph nodes and actual
  owners, not damage actors or coincidentally equal values.
- Preserve `NonExtraStat`'s Extra exclusion; ordinary `Stat` is not equivalent.
  Validate original-flat recipes against their original producer before later
  additions. Preserve observed evaluation count/order and cross-owner inputs.
  The trace provider is executing code, not necessarily the stat owner; bind
  coordinates to typed receivers, including foreign HP. Capture health-input
  expressions once at their original evaluation point, not by later rereads.
- Controlled stat-response probes preserve declaration/initialization order,
  seed and settings. Append stat changes; prepending a character can reorder
  the party and RNG. Diagnose schedule alignment separately from formula error.
  Test-runner success alone is not response acceptance. Generated overlays must
  resolve to the installed source, not an obsolete staging path.
- The one persisted energy switch is `gcsim_boosted_energy_enabled`. Infinite
  Selected maps to `ignore_burst_energy=true`; finite Selected/All Sets use
  `gtt_energy_ledger_v1`, artifact-ER deadline constraints and ordinary
  real-energy finalist verification. Theory fails closed in finite mode pending
  an ER-aware solver. Formula capture ignores burst costs to observe the full
  schedule; final verification applies real costs. Do not infer particles from
  action names or add a second setting. Report unavailable inventory feasibility
  explicitly.

## Real-backend button regression gate

Changes to optimizer launch paths, button wiring or the native consumer require
the explicit managed real-backend button gate, not only mocked wiring tests.
The public fixture exercises Selected/All Sets in fast and verified modes with
the selected installed engine and checks a reviewed numerical baseline; Theory
is excluded until accepted. The gate, baseline-review policy and launch-failure
receipts are linked from the current checkpoint. Offscreen buttons are not
physical app-window acceptance, and changed results never update the baseline
silently.

Search/ranking changes also use the accepted representative Chasca gate:
`tools/check_chasca_optimizer.py --app-root <checkout>`. Its fixed public600
inventory/profiles/rotation and reviewed normal-mode references are owned by
`docs/optimizer-evidence/2026-10-08-chasca-regression/README.md`. Keep the small
four-mode gate for fast-mode/launch coverage. A runtime above reference+5s
requests an idle-machine check and one isolated `--case` rerun, never an
automatic slower baseline. Different inventory or rotation is a different test.

## Parallel development boundary

The user-approved split keeps a reviewed checkpoint on `master`;
`codex/optimizer-polish` owns Selected/All Sets, and `codex/optimizer-theory`
owns Theory. The second checkout is `C:/Users/user/Desktop/worker2 GTT`.
Branch/folder readiness is not Theory acceptance or permission to change the
other worker's checkout. Share common fixes through reviewed commits, not
cross-folder writes; do not merge an unfinished Theory change into polish.
`tools/bootstrap_optimizer_worker.py` seeds a fresh registered linked checkout
through managed scratch, using a SQLite backup and verified active/rollback
engine copies. It excludes authentication, historical runs and research caches.
Launch from the worker's own directory; a reused Python environment is read-only.
