## Comparison boundary

`tools/experiments/gcsim/search_hypotheses/matrix_pair.py` runs one row only under
`tools/managed_optimizer_experiment.py`. It takes a consistent read-only SQLite
backup into managed scratch and prepares one request/source envelope through the
same adapter as the button. Both the installed optimizer and isolated combined
prototype receive those exact files, fixed seeds and the same active engine.
Fast mode requests7 groups ×7 rows to inspect leader and single-swap quality;
this is a formula-search gate, **not ordinary n500 or live UI acceptance**.
Search and whole CLI time are reported separately; compilation and shared
Python preparation are outside both CLI times. Later rows counterbalance binary
order; single-pair timings do not establish a statistical performance guarantee.

All exported assignments are checked against the frozen physical inventory,
wearer/slot identities, uniqueness, bonus-group signatures and single swaps.
Compare ranked leaders, retained groups, replacement quality/counts and capture
identities. A stronger new bonus group may replace a weaker old group legitimately;
identical group membership is not required for the heuristic variant. Leader
rank comparisons explicitly sort by DPS, not emitted group order. Exact-cache
variants must preserve all rows. Different capture sets need contextual review
because schedule-sensitive packages may differ; common captures must agree
under the existing expression/port/event canonicalizer. Raw hashes are retained
but changing local topological node IDs is not itself a semantic change.

The old20260919 matrix is retained unchanged as historical context. Its inventory
hash is unavailable; updated inventory does not prove heuristic recall or make
its old ordinary DPS directly comparable with new formula scores. Each new pair
retains its complete prepared request and input/engine/source/binary hashes.

## Lifecycle and review

No installation, active-engine change, equipment writes or GUI interaction.
Expanded source copies, binaries, snapshots, captures and runtime caches are
deleted by the managed runner. Receipts are capped at2MiB each and at three
attempts per unresolved row; no failed attempt is overwritten. Keep compact
evidence through integration acceptance, then retire rejected research helpers.
The parent reviews every row before authorizing the next; pause on a regression
or unexplained capture/legality discrepancy.
