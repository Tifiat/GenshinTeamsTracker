## Gate and lifecycle

Each row runs under `managed_optimizer_experiment.py`: one read-only account
snapshot, one immutable request/source envelope prepared through the application's
adapter, installed baseline and candidate using the same active engine and
fixed seeds. Fresh captures are compared by expression/event/owner semantics,
not incidental node IDs. Fast mode requests seven bonus groups with six
independent single-item swaps per group. This gate compares formula search;
ordinary simulator validation and application routing remain separate.

Luna executes one pair at a time; the parent reviews the result before releasing
the next. Keep every attempt. Inspect leader ranks, retained-group strength,
alternatives, legality, capture differences, stop reasons, time and memory.
Small deterministic changes are reviewed by gameplay impact, not mislabeled
simulation noise. A meaningful unexplained loss, invalid assignment or binding
failure stops the queue for diagnosis. Do not inject baseline builds into search.

Candidate source trees, binaries, account snapshots, capture files and caches
are disposable managed scratch. Cleanup must succeed before another allocation.
Compact JSON receipts are capped at2MiB each and retained through integration
review; at most three substantive attempts for one unresolved blocker. The
source-copy overlays and proposal generator are retired historical reproducers,
guarded against the old source identity, not another runtime backend. Keep them
with the failed and successful receipts; production regressions live in the
native tree. Deployment checks remain current. Do not change the active GCSIM
engine or account equipment.
