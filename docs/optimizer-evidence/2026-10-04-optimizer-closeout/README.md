## Численный контроль

Для проверки закреплён сохранённый Selected-запрос
`selected-20260928-122336-1a5e659e/request.json`, SHA256
`11532ecbe8925315e3f675c5b5680c72a7d32c2e1083a95d45af6e00927ab2ef`.
Это Беннет, Часка, Фурина и Оророн, 597 предметов; не Навия. Порядок
объявления персонажей, ротация, оружия и seed 742031889/742031890 сохраняются.
В копии входа меняется только `fast_mode=true`, чтобы не запускать лишнюю
обычную проверку финалистов.

Новый top1 взят через настоящий Selected-адаптер. Отдельно заменены перо
Часки на допустимое перо с наибольшей критмассой и её кубок на допустимый
АТК%-кубок с наибольшей критмассой среди неиспользованных альтернатив.
Исходный кубок тоже АТК%; изменение главного стата здесь не проверено.
Каждый вариант сравнивается с top1 независимо; предметы остальных персонажей
и бонусы наборов не меняются. Критмасса используется только для выбора проверочного
предмета, не как критерий ранжирования оптимизатора.

Контроль сопоставляет повторное использование формулы со свежей формулой
того же движка на каждом seed. Отдельно проверяется нейтральная модель
All Sets с тем же фиксированным сочетанием бонусов — без полного поиска
All Sets. Расхождение чисел, изменение расписания и неполное покрытие
зависимостей учитываются отдельно; совпадение в одной точке не доказывает
универсальную точность.

Все исходники-копии, сборки, кэши и сырые трассы принадлежат одной временной
задаче `managed_optimizer_experiment.py` и удаляются при выходе, в том числе
при ошибке. Лимит — 10 трассируемых seed: два исходных Selected, два без
наборов и по два на каждую из трёх сборок. Здесь допускаются максимум три
неперезаписываемых JSON-отчёта, каждый не более 128 KiB. Установленные движок
и оптимизатор не заменяются. Проверочный инструмент имеет 13 независимых
тестов на синтетических данных и не требует частного аккаунта в CI.

Первая попытка сохранена в [chasca-20261004.json](chasca-20261004.json):
четыре профильных Go-пакета и `vet` прошли, но проверочный файл не собрался
из-за отсутствующего `compactStrings`. Запуск Selected ещё не начинался,
трассируемых seed было ноль. В инструмент добавлена локальная функция
удаления повторных диагностических строк с проверками пустого списка и
дубликатов; производственный код не менялся. Временная задача удалена,
79 926 578 байт освобождены. Этот FAIL не заменяется результатом повтора.

Результат повтора сохранён в
[chasca-20261004-retry2.json](chasca-20261004-retry2.json) — 55 917 байт.
Сам инструмент завершился успешно; численный gate — нет. Четыре Go-пакета,
`vet` и проверка неизменяемых частей конфигурации прошли. Выполнены все
10 предусмотренных трассируемых seed, без обычных n500-прогонов. Свежий DPS
ниже — оценка новой формулы по заново полученной трассе, не обычный результат
симулятора с проверкой финалистов.

Разницы по seed889/890 соответственно: top1 +1745,384/+1214,075;

Порог проверки только округления — примерно 0,00015 DPS; это не допустимая
статистическая погрешность обычных независимых симуляций. Здесь одинаковый
seed не сохранил одинаковое расписание, поэтому чистая арифметическая ошибка
ещё не доказана. Вторая нейтральная модель с выбранными бонусами даёт ровно
те же три оценки, что и повторно используемая Selected-формула; это не полный
поиск All Sets и не доказательство точности всех бонусов.

Итоговые три сборки имеют одинаковое расписание друг с другом на каждом seed,
но оно отличается от исходной сборки: 383/363 попадания стали 383/372.
На первом seed количество сохранилось, а распределение стихий и реакций
изменилось. Например, заряженные Pyro/Electro/Hydro-попадания Часки:
33/28/37 в исходном расписании против 39/25/34 в новой сборке. Поэтому
сохранённый порядок top1 > перо > кубок — узкий положительный контроль,
а не закрытая проверка зависимости формулы от любых новых статов.

Перо1620 даёт относительно top1: −0,6 п.п. АТК%, −4,7 п.п. КШ,
+13,2 п.п. КУ, −37 МС, +239 HP. Его критмасса выше на 3,8 п.п., но
проверенные условия не сделали его сильнее. Кубок123: −35 АТК,
+6,2 п.п. КШ, −14,8 п.п. КУ, −19 DEF, +9,1 п.п. ВЭ, +5,8 п.п. HP%.
Всё это учтено вместе; прирост одной характеристики не проверялся изолированно.

Покрытие остаётся неполным: 31 тип необъяснённых зависимостей Selected,
38 причин ограничения нейтральной модели и четыре предупреждения её панели.
Следующая численная задача — отделить влияние изменившегося расписания от
замороженных зависимостей. Возможная связь с Фавонием Фурины и общей
случайной последовательностью — гипотеза по исходнику, не атрибуция по этим
числам. Новые прогоны, переработка RNG или расширение проверки не запускались.

Движок `gcsim-v2.45.0-20260927011932` и установленный consumer `76f8a52c`
не менялись; полные hashes есть в отчёте. Исходники Go этой проверки имеют
SHA256 `42f273cc730b8594da26c66bf570341c11247cf067ee6b63e29a1238cc9278f3`

чем исторический NUL-aggregate H4; hashes напрямую не сравниваются.
Временная задача удалена, 183 394 212 байт освобождены; сиротских задач нет.

Проверки использовали Python проекта с `-B`; интерфейс — с
`QT_QPA_PLATFORM=offscreen`. Живые проверки движка были выключены. Тесты
сохранения проверяют вызов с правильными данными, но не реальную запись пресета.
Повторные запуски тех же модулей не прибавлены к числу 123. Общая команда
для нового инструмента:
`.venv/Scripts/python.exe -B -m unittest tests.tools.test_optimizer_closeout_response -v`.

Первый прогон backend имел одну ошибку: тест ожидал одно упоминание capability
в patch stack, но нашёл два. Patch0001 добавляет определение; patch0009 только
содержит его в неизменённом контексте. Исправлен подсчёт добавленных определений,
а не движок. Добавлены проверки определения, контекста, удаления и дубликата.
После исправления backend прошёл 75 из 75; исходная ошибка не переписана в PASS.

При размере 1408 × 740 проверки подтвердили совпадение колонок основных и
заменяемых предметов, ограниченную ширину кнопок и отсутствие сдвига после
раскрытия или закрытия замен. Видимое поведение на экране пользователя ещё
не принято. Подсказка ускоренного режима использует штатное окно подсказок
и проверена для русского, английского и португальского переводов.
