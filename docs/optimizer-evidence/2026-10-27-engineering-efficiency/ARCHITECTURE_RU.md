# R3: исходная архитектурная проверка

Полный поиск, компиляция и запуск движка не выполнялись. Проверена точная
реконструкция R2: 411 файлов, 2 968 931 байт, карта
`5091c1ca4365c894b93db7685dc3e0d6905bdb226c1772b8cd06ab1fd0c64d14`.
Локальный необязательный архив исходников, 949 304 байта, SHA256
`56123cc8a4eac0af90e434553a1624e0aa226c13cfb4797589b9346476418924`, содержит
полный нативный модуль с go.mod. Первоначальная локальная квитанция сохраняет
682 прочитанные зависимости старой цепочки, включая импортированные модули
окружения; это не доказательство восстановления из чистого checkout.
После решения ROOT подготовлены [текстовая дельта](r2-source-delta-v1.patch) и
[манифест](r2-source-delta-v1.json): pinned Git `6f1cab8`, 211 изменённых файлов,
включая 153 отсутствовавших. `r3_recovery.py` побайтово восстанавливает точные
411 файлов без старых helpers, архива и грязного native. R3 overlay использует
эту процедуру при отсутствии локального архива; несовпадение закрывает путь.
Python/button и исходники producer в этот архив не входят: их прежние цепочки
восстановления и привязки остаются отдельными.

## Сохранённые данные

В [машинной квитанции](architecture-inputs-v1.json) зафиксированы два реальных
исторических захвата Часки, семена 742031889/890. IR: 9 127 421/9 078 672 байта,
88 579/88 122 узла, 372/366 каналов. Sidecar: 15 245 163/15 084 697 байт, есть
neutral и energy ledger, сохранены config/request и полные SHA256. Это позволяет
измерять кодек, валидацию, компиляцию графа и выделение памяти без полного поиска.

Это не удалённые payload R2: source manifest и context другие, секции
mechanic_invocations нет. Поэтому их результаты не доказывают полную стоимость
нынешнего f1e sidecar или точность R2 на этих данных. Новый захват пока не нужен
для сравнения IR-кодека; необходимость актуального capture-only ввода решает ROOT.

## Один предлагаемый вариант транспорта

Предлагается **типизированная канонизация существующего JSON IRSeedMember**:
использовать сохранённый, ранее не запущенный typed-canonical view как кандидат
для R3, отдельно измерить его. Нынешний decodeStrict после типизированного
декодирования создаёт raw generic DOM, затем снова marshal/decode generic DOM
для typed значения. Кандидат убирает только второй generic DOM, сериализуя
типизированные поля в лексикографическом порядке. Формат/байты экспорта,
размер передачи, producer f1e и sidecar остаются прежними. Это один typed вариант;
новый бинарный протокол пока не предлагается без измеренного оправдания.

Сохраняются DisallowUnknownFields, EOF, raw-vs-typed canonical equality,
ValidateSeedMember, nil/empty, optional/pointer presence, decimal strings,
точные целые числа и прежнее поведение стандартного JSON decoder. Нельзя заменять
эту проверку одним успешным unmarshal. Обязательны побайтовая canonical/SHA parity,
сложные строки/числа, malformed/unknown/missing/null и проверка структуры зеркала
схемы. Публичный CanonicalJSON произвольных значений остаётся прежним.

Идентичность цепочки: проверенный binary/source binding; точный config SHA;
выбранное семя; raw member SHA в sidecar; source manifest, resolved config,
actor/channel/node/event ownership; нейтральные ссылки и mechanic bindings.
IR validator сохраняет contiguous/topological IDs, допустимые операции/arity,
каналы, opaque coverage, конечные числа и energy ledger. Sidecar validator и
внешние request/frame/graph identities не обходятся. Для любого будущего binary
варианта потребуются отдельные capability/version, строгие длины/наличие полей,
эквивалентное nil/empty и семантическое связывание вместо raw JSON digest;
обычный JSON должен сохраниться. Эти exporter-изменения сейчас не разрешены.

Измерение после выбора ROOT: одинаковый сохранённый IR, ограниченные повторы
baseline/candidate, encode + файловый transfer + DecodeSeedMember/validation +
CompileSeedMember; отдельно allocations, живой heap после GC и байты. Sidecar
измеряется отдельно как неизменённая стоимость, без заявления ускорения exporter.
Исторический архив распаковывается за пределами измерения. Нельзя объявлять
выигрыш всей цепочки по одному времени decoder.

## Независимо разрешённая реализация

- Два seed child одновременно, максимум два; отдельные каталоги, результат в
  порядке исходных семян, cancel и join всех детей, квитанции после join.
  Отдельно общий wall и сумма process/decode. Проверка producer до/после batch.
- Adjoint buffer принадлежит ArtifactProgram scratch. Возвращаемый gradient
  по-прежнему новый; copyArtifactScratch/ForkTheory не разделяют mutable adjoints.
  Арифметика и порядок обратного обхода не меняются.
- Обратная pointer-to-key карта только для уже сохранённых programCache entries;
  удаление при FIFO eviction, сброс/перестроение при fork, прежние лимиты и ключи.
  Нового кэша symbolic groups нет: повторяемость пока не доказана.

Модули имеют отдельные переключатели. Следующий этап — focused offline/parity/
ownership/race проверки и ограниченные измерения; полный Chasca button до
отдельного допуска ROOT закрыт. Ничего не установлено.
