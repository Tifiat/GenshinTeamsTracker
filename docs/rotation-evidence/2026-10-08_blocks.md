## Как связаны код, текст и свойства

Единственный редактируемый документ — дерево исходного кода с привязками к
его участкам. Над ним распознаются понятные пользователю конструкции:
«цикл из четырёх ротаций», «в каждой нечётной ротации», действия персонажей.
Это вычисляемые представления, а не второй документ, который нужно отдельно
синхронизировать. Переведённая строка никогда не разбирается обратно в код.

Выбор блока даёт его идентификатор. Общая панель запрашивает свойства этого
блока; изменение свойства меняет соответствующие узлы исходного дерева.
После изменения читаемое представление строится заново. Создание блока
кнопкой использует те же узлы и тот же распознаватель, что импорт кода.
Так новая кнопка не требует второго переводчика.

Четыре области будущего редактора:

1. **Документ:** вложенные кликабельные блоки, выделение и удаление крестиком.
2. **Команды:** навигация по действиям; выбор персонажа меняет команды,
   кнопка «Назад» возвращает предыдущий набор.
3. **Общая контекстная панель:** свойства выбранного персонажа, действия,
   цикла или условия. «Личные механики» — содержимое этой панели для
   подходящего контекста, а не обязательный дополнительный блок в документе.
4. **Категории:** вкладки или крупные кнопки появляются, если объём команд
   требует разделения. Точные категории и компоновка определяются по содержимому.

Отдельное разворачиваемое окно остаётся рабочим направлением. Геометрия,
физические кнопки и их установка в AppShell в этот этап не входят.

«Работает» ниже означает изолированное ядро и текстовый preview, не готовый UI.
«Структура есть» означает сохранение/генерацию исходных узлов; простой
пользовательский редактор этих свойств ещё предстоит сделать.

Системные функции не потеряны из охвата. Полный словарь перечисляет все 24:
время (`f`, `wait`, `sleep`, `delay`), действия (`execute_action`), геометрию
и цели (`set_target_pos`, `set_player_pos`, `set_default_target`, `kill_target`,
`is_target_dead`), настройки задержек (`set_swap_icd`, `set_particle_delay`),
объекты (`pick_up_crystallize`, `set_starting_verdant_dew`), математику
(`sin`, `cos`, `asin`, `acos`, `is_even`, `rand`, `randnorm`), служебные
(`print`, `type`) и обработчик `set_on_tick`. Это группы для дальнейшего
проектирования, не утверждённые вкладки и не готовые простые кнопки.

## Проверенный пример

Текст, полученный текущим preview из неизменённого публичного fixture:

```text
Цикл из 4 ротаций
  В каждой нечётной ротации
    Фурина
      Элементальный навык
      Рывок
      Взрыв стихии
  Оророн
    Взрыв стихии
    Элементальный навык
  Беннет
    Элементальный навык
    Взрыв стихии
  Часка
    Элементальный навык
    Прицельная атака × 4
    Прицельная атака; Количество пуль: 4
    В каждой нечётной ротации
      Взрыв стихии
Ждать 82 кадров от момента разрешённой очереди действий
```

`i=0` и `is_even(i)` выбирают первую и третью человеческие ротации.
Импорт не переписывается. Четыре локализованных имени внедряются из явно
помеченного публичного preview fixture; это не новая база имён приложения.
При интеграции resolver должен использовать подготовленные записи проекта.

Часке здесь намеренно ещё не назначено название особой атаки автоматически:
`aim` внутри действующего навыка стреляет пулями, вне него выполняет обычный
прицельный выстрел. Второй `skill` во время действующего навыка завершает режим.
Поэтому чтение кода не вставляет навык и не удаляет повторное нажатие.
Будущий контекстный вариант «особая атака» должен явно создавать необходимые
действия и учитывать уже созданные; проверка времени/кулдаунов отдельным
прогоном остаётся идеей, а не реализованным статическим обещанием.

## Границы распознавания и обратные изменения

| Код или изменение | Результат |
| --- | --- |
| `for let i=0; i<4; i=i+1 { … }` | Цикл из 4 ротаций |
| `for let n=1; n<=4; n=n+1 { … }` | Та же пользовательская конструкция |
| Сменить число 4 на 6 в первом варианте | Меняется только граница `i<6`; тело и нетронутые комментарии сохраняются |
| `if is_even(i)` при начальном `i=0` | В каждой нечётной ротации |
| Выбрать чётные ротации через свойства | Генерируется условие для человеческих номеров 2, 4…; исходные действия и `else` сохраняются |
| Выбрать номера 1 и 4 | Генерируются сравнения, объединённые «или» |
| Сократить цикл до 3 при выбранной ротации 4 | Изменение отклоняется, выбранная ротация не исчезает молча |
| В теле изменяется счётчик, есть неизвестный вызов, замыкание или `return` | Подробный особый цикл; фиксированное число не обещается |
| Есть callback `set_on_tick` | Счётные циклы не упрощаются: обработчик способен менять счётчик |
| `is_even` переопределён пользователем | Вызов не выдаётся за расписание |
| Внутреннее условие относится к внешнему циклу | Хранится ссылка именно на внешний цикл и показывается уточнение |
| Незавершённый новый блок | Видно «Необходимо вставить действие»; готовый код не выдаётся |

В GCSL нет `%`. Расписание использует целочисленное деление и сравнение,
а не неподдерживаемый оператор. Распознавание работает только в доказанном
диапазоне целых; сравнения выбранного движка используют float64. Неизвестная
форма остаётся доступной в исходном виде. Один успешный разбор не доказывает
выполнение всех действий, отсутствие ожидания кулдауна или окончания симуляции.
