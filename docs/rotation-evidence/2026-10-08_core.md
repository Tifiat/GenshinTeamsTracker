## Implemented and verified boundary

- One immutable source-linked editor tree feeds code generation and Readable.
  Future structured buttons create/edit the same nodes. Source character
  offsets, UTF-8 byte conversion, explicit draft holes, local unknown recovery,
  source-preserving edits, comments, repeats, function bodies/types, control
  blocks and setup envelopes are retained.
- Readable includes all eleven action names and descriptions of the selected
  24 system-function names in existing RU/EN/PT-BR locale files. It preserves
  arguments, duplicate/overridden entries, scopes and control flow; direct
  control and blocks with both terminating branches mark unreachable tails.
  Builtin shadowing/assignment and an overridden execute_action are represented
  conservatively. It does not infer a combat action from an unknown function.
- Explicit swaps and implicit switches use the same character windows. Initial
  active is a global setting; its final occurrence applies before runtime
  actions. Conditional/dynamic actor state stays uncertain. Conditions about
  another character do not create that character's window. Repeat zero does
  not activate its target.
- Selected setup typing and identity-bound character option checks are separate
  from syntax parsing. Session commit checks regenerated structure and applicable
  typed rules without destroying the draft on failure. Runtime action readiness,
  energy availability, option constraints described only in prose and arbitrary
  user-function types are not fully validated.
- Generated registry adapter reads only the explicitly supplied source's
  `pkg/core/keys/character.dm.go` and `pkg/shortcut/character.dm.go`.
  Source aliases do not require a second name database. Public docs tables supply
  separate Actions/Params/Fields; unsupported mechanics retain explicit keys.
  Chasca bullet condition fields remain curated: they are absent from Fields.
- Async option service has prepare/select entrypoints, request deduplication,
  current-engine identity checks, stale-reply exclusion, partial/offline fallback
  and revision-pinned official fetch. Opaque executable version strings are not
  treated as public source commits. New grammar is not inferred from a new roster.
- Cache schema/checksum, atomic replacement, finite count/byte bounds and connected
  cleanup are implemented. Defaults: 32 entries / 4 MiB, at most two workers,
  64 outstanding physical jobs and two controlled attempts; official tables at
  most 2 MiB each, five-second wait per table. Cleanup protects rotations,
  supplied dictionaries, symlinks, future-format files and active current-format
  temporary files; obsolete known formats are rebuilt and abandoned temporary
  files expire after an hour. Tests use only TemporaryDirectory.

## Reproduce a read-only preview

```powershell
.venv/Scripts/python.exe -B -X utf8 tools/preview_rotation_editor.py --engine-root data/gcsim/engines/engines/gcsim-v2.45.0-20260927011932 --audited-v245 --character chasca
```

The default input is the existing public fixture; `--file` accepts an explicitly
selected rotation, `--language` selects ru/en/pt-br, `--canonical` prints regenerated
code. The CLI does not load application settings, fetch metadata or create cache.
It prints stable keys for character names because the production name resolver
is not connected. Character metadata exposes original official descriptions,
including untranslated English where no curated translation exists.
