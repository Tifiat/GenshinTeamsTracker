# Словарь ротаций GCSIM: таблица для обсуждения

Дата: 2026-10-08. Это датированное исследование и предварительная классификация.
[READABLE_ROTATION_EDITOR.md](../handoff/READABLE_ROTATION_EDITOR.md) остаётся
единственным владельцем текущих требований. Здесь нет установленного
переводчика, утверждённой панели или очереди реализации.

## Как читать таблицы

Сложность относится к самостоятельному составлению ротации:

| Метка | Что означает | Предварительный способ представления |
| --- | --- | --- |
| A — прямое действие | Понятное действие с явно заданным участником | Текстовый шаблон с выбором персонажа |
| B — действие с контекстом | Значение/единица/допустимость зависят от персонажа, параметров или соседних действий | Тот же шаблон плюс проверяемые поля |
| C — составная логика | Нужно собрать условие, ветви, цикл или числовое выражение | Вложенные блоки и отдельный словарь условий |
| D — программа | Переменные, функции, случайность, обработчики и изменение исполнения | Структурное объяснение и доступный исходник; доступность кнопок обсуждается отдельно |
| S — настройка | Состав команды, экипировка, цели или параметры симулятора | Отдельная часть Readable; место в редакторе позже |
| X — вне выбранной версии/устаревшее | Документация описывает другую версию или прежний синтаксис | Исходник и точное пояснение поддержки |

Это не готовый перечень кнопок. Однозначно перевести название `skill` проще,
чем составить корректную последовательность навыков: перевод и боевое
исполнение — разные проверки. «A» не означает доступность действия у каждого
персонажа или достаточную энергию в бою. Переводчик отображает инструкцию и
условия из кода, не наблюдает бой и не выбирает ветвь за автора.

## 1. Все действия персонажа и формы записи

У lexer выбранной версии 11 имён действий. `sleep`/`wait`/`delay` —
вызовы функций, а не двенадцатое действие после имени персонажа.

| Категория | Код / форма | Читаемый смысл | Параметры и существенная граница |
| --- | --- | --- | --- |
| A/S | `active furina;` | Начальный персонаж: Фурина | Настройка начального состояния всего config. Последняя такая настройка имеет силу; положение среди строк не делает её переключением во время боя. Внутри gcsl-блока не является действием |
| A | `c swap;` | Сделать активным указанного персонажа | Runtime-переключение. Нельзя подменять его строкой `active` |
| A | `c attack;` | Обычная атака указанного персонажа | Одно действие нормальной цепочки, не обязательно один удар по врагу |
| A | `c skill;` | Элементальный навык | Вариант навыка уточняют параметры конкретного персонажа |
| A | `c burst;` | Взрыв стихии | Действие может ждать готовности/энергии при исполнении. Перевод её наличие не доказывает |
| A | `c dash;` | Рывок | Особые варианты рывка и его параметры относятся к B |
| A | `c jump;` | Прыжок | Состояние персонажа может ограничивать исполнение; например Часка во время Nightsoul |
| B | `c walk;` | Ходьба / действие walk | Полная модель перемещения и frame-данные имеются не у всех; не обещать заданное расстояние |
| B | `c aim;` | Прицельный выстрел | Для лучников; у Часки смысл зависит от состояния. У Фурины это недопустимое действие |
| B | `c charge;` | Заряженная атака | Может требовать предыдущую обычную атаку либо другой контекст. Часка использует `aim`, её `charge` недопустим |
| B | `c low_plunge;` | Атака в падении с малой высоты | Нужен допустимый переход/воздушное состояние; `collision` не общий флаг любого действия |
| B | `c high_plunge;` | Атака в падении с большой высоты | Зависит от персонажа и предыдущего действия |
| A | `c skill, burst;` | Последовательно выполнить навык, затем взрыв стихии | Порядок сохраняется; это две команды, не совместное действие |
| A | `c attack:3;` | Выполнить действие «обычная атака» × 3 | Повтор одного действия. Не «три отдельных попадания», не три полные ротации |
| B | `c skill[hold=1];` | Выполнить вариант навыка, заданный параметром hold | Значение/единица выбираются по схеме `версия + персонаж + действие + параметр` |
| B | `c aim[bullets=4]:2;` | Два прицельных действия с параметром «пули: 4» | Сначала параметры, потом `:N`. Поддержка числа пуль подтверждена для Часки |

Префикс персонажа в действии обязателен. Если указанный персонаж неактивен,
штатный `execute_action` вставляет переключение. Readable показывает явно
указанного участника; он не должен заменять его первым участником команды.
Сама форма `attack;` без персонажа не становится действием текущего персонажа.

В будущих шаблонах «для текущего персонажа» участник может быть выбран раньше,
но перед генерацией кода должен быть однозначно связан с ключом. После разных
ветвей `if` активный участник может различаться. Не превращать обводку блока
в утверждение об общем активном персонаже для обеих ветвей.

## 2. Полный словарь состава программы

| Категория | Конструкция | Как объяснить в Readable | Что требуется от структуры |
| --- | --- | --- | --- |
| A | Последовательность `stmt; stmt;` | Выполнить команды по порядку | Не переставлять шаги и не удалять команды с неясным смыслом |
| A | `# ...`, `// ...` | Комментарий автора | Только до конца строки; сохранять исходник, учитывать кавычки |
| B | Числа, `true`, `false` | Число; да/нет | В условиях 0 — ложь, ненулевое число — истина; bool-литералы сводятся к 1/0 |
| B | `(expression)` | Группа выражения | Скобки/приоритет операций сохраняются |
| C | `if p { A }` | Если p, выполнить A | Условие и действия — отдельные места заполнения; может не выполниться ни одного действия |
| C | `if p { A } else { B }` | Если p — A, иначе — B | Обе ветви видимы. Перевод не выбирает результат условия |
| C | `else if p { ... }` | Иначе, если p | Цепочка ветвей с сохранением порядка |
| C | `while p { A }` | Повторять A, пока выполняется p | Проверка перед первым выполнением и перед каждой следующей итерацией |
| C | `while 1 { A }` | Повторять A до остановки симуляции | Не приписывать предел по времени/числу, которого нет в коде. Цикл должен давать симулятору продвигать время |
| C | `for let i=0; i<4; i=i+1 { A }` | Повторить A с i от 0 до 3 | Число повторов можно объяснять лишь для подтверждённой схемы счётчика, не для любого for |
| C | `for p { A }`, `for { A }` | Цикл с условием; цикл без условия | Дополнительные формы выбранного parser. Пустой заголовок не означает одно выполнение |
| C | `break;` | Выйти из ближайшего цикла или switch | Принадлежность управляющему блоку обязательна |
| C | `continue;` | Перейти к следующему шагу ближайшего цикла | Не прятать пропуск остальных действий тела |
| C | `switch e { case v: A default: B }` | Выбрать ветвь по значению e | В обычном switch сравниваются значения; default применяется при отсутствии совпадения |
| C | `switch { case p: A ... }` | Выбрать первую подходящую ветвь условия | Поддерживается выбранным parser; иная форма, чем switch по одному значению |
| C | `fallthrough;` | Продолжить также следующую ветвь switch | Не равно обычному «иначе» |
| C | `+ - * /` | Числовое выражение | Сохранить операнды и порядок; не вычислять игровой результат в переводчике |
| C | `== != < <= > >=` | Равно; не равно; меньше/больше; с равенством | Сравнивать совместимые величины. Значение поля не всегда время |
| C | `&& \|\| !` | И; или; не | Все части и отрицания видимы. Приоритет `&&` выше `\|\|` |
| C/D | `let x = expression;` | Создать переменную x с указанным значением | Объявление, область видимости, обязательное начальное значение |
| C/D | `x = expression;` | Изменить значение x | Нельзя переводить имя переменной как новое действие |
| C/D | `{ ... }` | Вложенный блок | Граница области видимости, а не только декоративная рамка |
| D | Строка `"text"` | Строковое значение | Сохранять экранирование; `#` и `;` внутри кавычек не комментарий/граница команды |
| D | `[key=expression,...]` | Набор именованных параметров | Map-выражение, не последовательность действий. Одинаковые/неизвестные ключи требуют диагностики |
| D | `let x number/string/map/fn(...) = ...;` | Переменная с явно указанным типом | Parser поддерживает типы шире старого описания «только числа»; не угадывать тип по русскому тексту |
| D | `fn name(args) type { ... }` | Определить функцию с аргументами и телом | Типы аргументов/результата, вложенность и scope |
| D | `let g = fn(args) { ... };` | Сохранить функцию в переменную | Типизация/анонимная функция требуют отдельной схемы |
| D | `name(args);` | Вызвать функцию с указанными аргументами | Имя может быть пользовательским; описание реализации не следует из одного имени |
| D | `return expression;` | Вернуть значение из функции | Не «завершить ротацию» |
| D | Переопределение встроенной функции | Дальнейшие команды исполняются через изменённую функцию | Нужно разрешение имён/привязок. Простая замена `skill` словами уже недостаточна |
| X | `restart`, `wait 10;`, `mode=apl` | Прежний синтаксис / несовместимый режим | Материал миграции не добавляет текущие команды |
| X | `label`, `until` из lexer | Зарезервированные слова без подтверждённой инструкции | Их наличие в таблице токенов не доказывает поддержку конструкции |
| X | Оператор `%`, `++` как предполагаемый shorthand | Неподтверждённый синтаксис | Процент в имени stat-key не оператор остатка. Использовать только реально принятую грамматику |

[Typed declarations](https://github.com/genshinsim/gcsim/blob/20d8f7706cc7209afffd6f21aff351c7d9a73398/pkg/gcs/parser/parseTyping.go),
[функции](https://github.com/genshinsim/gcsim/blob/20d8f7706cc7209afffd6f21aff351c7d9a73398/pkg/gcs/parser/parseFn.go),

## 3. Все зарегистрированные системные функции

В выбранном source 24 имени, включая оба алиаса `sleep`/`wait`.
В новом справочнике дополнительно описана `movement`, которой нет в реестре
этой установки. Функции могут быть командами или частями выражений.

| Категория | Функция | Смысл, аргументы и единицы | Граница для Readable/шаблонов |
| --- | --- | --- | --- |
| B | `sleep(n)` | Пауза по правилам очереди на n кадров | Начинается после CanQueueAfter предыдущего действия; не обязательно добавляет n кадров после всей анимации |
| B/X | `wait(n)` | Алиас sleep, сохранённый в выбранной версии | Документация предпочитает sleep; исходный wait автоматически не заменять |
| B | `delay(n)` | Добавить задержку перед следующим действием, n кадров | Отличается от sleep; применяется перед проверкой готовности следующего действия, hitlag может увеличить наблюдаемое время |
| B | `pick_up_crystallize("element")` | Попытаться подобрать кристалл выбранного элемента или `"any"` | Может вернуть 0 или 1; «попытаться» не равно гарантированно подобрать |
| B/S | `set_default_target(n)` | Выбрать основной target для последующих действий | Индекс функции от 1; target-поля t0/t1 начинаются с 0 |
| B/S | `set_player_pos(x,y)` | Установить координаты игрока в метрах | Не обычный шаг ходьбы заданной длины |
| B/S | `set_target_pos(n,x,y)` | Установить позицию цели n в метрах | Индекс функции от 1, нужны реально существующие targets |
| C | `f()` | Текущий номер кадра | Часть условия/выражения; не секунды |
| C | `is_even(n)` | Проверка чётности числового аргумента | Нужна область видимости аргумента и его числовой тип |
| C/D | `is_target_dead(n)` | Проверить смерть указанной цели | Выбранный runtime требует damage mode; экспериментальная функция в справочнике |
| D | `rand()` | Случайное равномерное число | Не переводить как фиксированную вероятность успеха отдельной команды |
| D | `randnorm()` | Случайное число нормального распределения | Параметры распределения задают дальнейшей арифметикой |
| D | `sin(n)` | Синус числового аргумента | Математический элемент выражения |
| D | `cos(n)` | Косинус числового аргумента | Математический элемент выражения |
| D | `asin(n)` | Арксинус числового аргумента | Математический элемент выражения |
| D | `acos(n)` | Арккосинус числового аргумента | Математический элемент выражения |
| D | `print(args...)` | Вывести значения/строки в log | Диагностика, не боевое действие и не продвижение времени |
| D | `type(value)` | Получить название типа значения | Служебное выражение, не персонажный selector |
| D | `execute_action(char,action,params)` | Вызвать низкоуровневый исполнитель | Числовые ключи и map; возможны overrides. Экспериментальный API, не универсальная обычная кнопка |
| D | `set_on_tick(fn)` | Подключить функцию, выполняемую каждый кадр | Callback может менять последующее поведение; нельзя безусловно свернуть в плоскую ротацию |
| D/S | `set_particle_delay("c",n)` | Изменить задержку частиц указанного персонажа в кадрах | Реальный ключ участника, изменяет конфигурацию последующих событий |
| D/S | `set_swap_icd(n)` | Изменить общий cooldown переключений в кадрах | Особый режим поведения, в документации связан с booking, не обычный swap |
| D/S | `kill_target(n)` | Принудительно уничтожить target | Это не атака и не «атаковать до смерти». Требует damage mode |
| S | `set_starting_verdant_dew(n)` | Начальный Verdant Dew, целое 0…3 | Только в начале, до превышения frame 1 |
| X | `movement(n)` | Новая документированная функция регистрации движения | Не зарегистрирована в выбранном v2.45.0; новый сайт не основание генерировать её здесь |

При переводе вызова не добавлять функции отсутствующие аргументы/лимиты.
Некоторые строки нового справочника называют возвращаемым значением 0, тогда
как выбранный source возвращает null/bool. Тип для арифметического использования
определять по выбранному source; не заменять любое служебное значение числом 0.

## 6. Разные примеры кода и читаемого смысла

Примеры ниже — фрагменты, не полные готовые sim-config. Авторские примеры не
запускались; их синтаксические формы/значения опираются на указанные источники.
Поведение и качество ротаций не оценивались.

### Прямые действия — A

```text
active furina;
furina skill, burst;
chasca skill;
```

Читаемый смысл: «Начальный персонаж: Фурина. Фурина: элементальный навык,
затем взрыв стихии. Переключиться на Часку и выполнить её элементальный навык».
Переключение следует из следующего явно указанного участника, не из замены
`active` во время ротации.

### Одинаковое имя параметра — разные схемы — B

```text
bennett skill[hold=2];
nahida skill[hold=60];
chasca aim[bullets=4]:2;
```

Читаемый смысл: «Беннет: удерживаемый навык второй ступени. Нахида: удерживаемый
навык с параметром удержания 60 кадров. Часка: выполнить прицельное действие
с четырьмя пулями два раза». У Нахиды hold добавляется к минимальному переходу
Tap→Hold, а не обещает итоговую анимацию ровно в одну секунду. Число выстрелов
Часки — повтор действия, не гарантированное число попаданий.
[Params выбранного тега](https://github.com/genshinsim/gcsim/blob/20d8f7706cc7209afffd6f21aff351c7d9a73398/ui/packages/docs/src/components/Params/character.dm.json).

### Зависимость от следующего действия — B/C

```text
neuvillette charge[ticks=3], dash;
```

«Нёвиллет: заряженная атака с тремя тиками, затем рывок».
Для укороченной такой атаки справочник ограничивает следующий шаг вариантами
Burst/Skill/Dash/Jump. Просто позволить любой следующий шаг после поля «тики»
недостаточно. Окончательную возможность исполнения проверяет движок.

### If/else — C, два самостоятельных сценария

```text
if .furina.burst.ready {
  furina burst;
} else {
  furina skill;
}
```

«Если внутренняя проверка готовности взрыва стихии Фурины успешна — выполнить
взрыв стихии; иначе — элементальный навык».
Ни энергию, ни результат этого условия переводчик не вычисляет.

### While — C, проверка перед каждой итерацией

```text
while .furina.status.favonius-cd == 0 {
  furina attack;
}
furina dash;
```

Точный читаемый смысл: «Пока личный откат favonius-cd у Фурины равен нулю —
выполнять обычные атаки Фурины. После выхода из цикла — рывок».
Условие проверяется перед первой атакой; число атак может быть нулём.
Это свойство записанного `while`, не решение переводчика.

У [Меча Фавония](https://docs.gcsim.app/reference/weapons/favoniussword/)
нет собственного опубликованного списка fields. Ключ проверен в
[общем Favonius runtime](https://github.com/genshinsim/gcsim/blob/20d8f7706cc7209afffd6f21aff351c7d9a73398/internal/weapons/common/favonius.go):
личный статус владельца, не core-status и не tag. Если принадлежность оружия
подтверждена выбранной командой, доступно название из каталога. Без этого
подтверждения сохраняются ключ и пояснение, а не выдуманное оснащение.
«До нового срабатывания» не следует автоматически из «откат равен нулю».

### If вокруг группы и вложенный while — C

```text
if .furina.status.favonius-cd == 0 {
  furina skill;
  while .furina.status.favonius-cd == 0 {
    furina attack;
  }
} else {
  furina dash;
}
```

«Если при входе в группу откат не действует: выполнить навык, затем повторять
обычные атаки, пока откат не действует. Иначе: рывок».
Здесь `if` выбирает всю группу, а `while` отдельно проверяет повторяемое
действие. Для `if p { while p { A } }` без дополнительных действий и без
побочных эффектов в p внешняя проверка избыточна; её нельзя описывать как
обязательный иной боевой сценарий.

### Составное условие и явно записанный предел — C

```text
while .furina.status.favonius-cd == 0 && f() < 600 {
  furina attack;
}
```

«Повторять атаки, пока одновременно откат равен нулю и текущий кадр меньше 600».
Это предел от начала симуляции, а не «ещё 10 секунд после входа в блок».
Переводчик не добавляет такой предел в первый пример. Относительный предел
нужно выразить отдельной переменной/выражением.

### Реальный публичный фрагмент приложения — C

Из [rotation_chasca_ororon_furina_bennett.txt](../../run_workspace/gcsim/smoke_fixtures/rotation_chasca_ororon_furina_bennett.txt):

```text
for let i=0; i<4; i=i+1 {
  if is_even(i) {
    furina skill, dash, burst;
  }
  ororon burst, skill;
  bennett skill, burst;
  chasca skill;
  chasca aim:4;
  chasca aim[bullets=4];
  if is_even(i) {
    chasca burst;
  }
}
wait(82);
```

«Четыре прохода с i=0,1,2,3. На чётных i Фурина выполняет навык, рывок,
взрыв стихии. Каждый проход: Оророн — взрыв стихии и навык; Беннет — навык и
взрыв стихии; Часка — навык, четыре прицельных действия, ещё одно с четырьмя
пулями; на чётных i — её взрыв стихии. Затем ожидание wait на 82 кадра по
правилам очереди». Чётные значения здесь — первый и третий проходы.
Fixture публичный backend/dev input; это не реальный профиль и не приёмка боя.

### Неоднозначный активный персонаж после ветвей — C

```text
if .furina.burst.ready {
  furina burst;
} else {
  chasca skill;
}
sleep(10);
```

«В одной ветви действие выполняет Фурина, в другой — Часка; затем пауза».
После ветвей нельзя сделать один заголовок «Фурина активна». Следующее
`chasca aim;` имеет явного участника; следующий шаблон «навык текущего»
требует однозначного контекста.

### Функция и цикл — D

```text
fn rotate() {
  furina skill, burst;
  chasca skill, aim:4;
}
while 1 {
  rotate();
}
```

«Определить функцию rotate с указанной последовательностью; повторять вызов
rotate до остановки симуляции». Definition и call сохраняются отдельно.
Не требуется исполнять функцию в переводчике или размножать её тело в коде.
Overrides `execute_action` и callbacks требуют ещё более осторожного
разрешения имён; неоднозначный фрагмент остаётся исходником.

## 7. Проект переводчика и будущая обратная сторона

Предлагаемая общая структура: `исходник → разбор → дерево команд → Readable`.
Будущие шаблоны меняют это же дерево; генератор получает его и выдаёт gcsl.
Обычная фраза в чат-строке — отдельный необязательный вход, не замена этому
ядру. Код сохраняется целиком; диапазоны включают источник диагностики.

Минимальные узлы: настройка, действие (участник/параметры/повтор), последовательность,
условие с ветвями, цикл, выражение, объявление/вызов функции, исходный фрагмент.
Каждый узел хранит диапазон Code, ключи сущностей, версию схемы, вложенность
и диагностику. Выражение содержит операнды/оператор/скобки/тип величины.
Текст интерфейса строится из `tr_for_language` и существующих каталогов
RU/EN/PT-BR; переводимые имена не участвуют в определении GCSIM identity.

Для произвольных имён подходят нейтральные подписи «Персонаж: …»,
«Эффект оружия «…»», «Условие: …»; они не требуют склонять тысячи имён.
Fallback: имя на выбранном языке → доступное имя по фиксированному порядку →
стабильный ключ с пояснением. Тяжёлая морфология и новый каталог не требуются.

Удобство составления определяется типизированными местами: участник, действие,
параметр, условие, тело, иначе. Их незаполненность видима; генерация не должна
создавать недостающие участники/условия самостоятельно. При смешанном Code
неподдержанный узел сохраняет исходник и местное пояснение. Текущий ввод и
последний полностью разобранный текст различаются.

Для будущей проверки нужны сохранение исходника, обратный разбор сгенерированного
кода в ту же структуру, контроль scopes/типов/единиц/контекста и независимые
пары «код → смысл». Никакой такой проверки сейчас не выдано за реализованный
переводчик. Наличие синтаксически правильного дерева не доказывает выполнимость
боевой ротации.

## 8. Небольшая локальная модель: предварительная оценка

Для Code → Readable достаточно грамматики и шаблонов: разнообразие исходного
языка структурно определено. Такой слой может быть полностью локальным и
детерминированным. Сначала он нужен всем трём пользовательским сценариям.

Свободный текст → код технически возможен отдельным помощником. Есть
[малые модели, например Qwen3-0.6B](https://huggingface.co/Qwen/Qwen3-0.6B), и
[llama.cpp с ограничением вывода грамматикой/JSON Schema](https://github.com/ggml-org/llama.cpp/blob/master/grammars/README.md).
Модель можно обязать выдавать допустимую структуру команд. **Из этого не
следует, что она верно поняла отрицание, участника, границу цикла или намерение
«новое срабатывание»**. Схема ограничивает форму, не заменяет смысловую проверку.

Размер одних 0.6B весов при идеальных 4 bit на параметр — расчётно около
300 MB; реальный файл, runtime и рабочая память имеют дополнительные расходы.
Это оценка порядка размера, не замер конкретного GGUF и не рекомендация модели.
[GGUF у разработчиков llama.cpp](https://huggingface.co/ggml-org/Qwen3-0.6B-GGUF)
и встроенный runtime позволяют рассматривать упаковку без ручной настройки
Python пользователем. Конкретные CPU/RAM/задержка и размер установки здесь
не измерялись и не обещаются.

Пары `gcsl → канонический Readable` полезны как точная основа обучения.
Однако они сами не покрывают разговорные формулировки, пропущенные параметры,
неоднозначности и разные языки. Понадобятся перефразирования, отрицательные
примеры, раздельные train/test на разных структурах, проверки intent и
адаптация к версиям реестра. Точность перевода тут отдельна от качества/DPS
ротации; хороший DPS для такого набора не нужен.

Предварительный вывод исполнителя: свободный чат-ввод реалистичен как
необязательный помощник после общего дерева/валидатора/Readable, с показом
получившегося смысла. Обещание «маленькая модель без ошибок» не обосновано.
Для первого этапа модель не нужна; шаблоны с явными полями могут охватить
категории A/B и затем C без её обучения. Доступность C для казуального
пользователя ещё следует проверить на примерах общего словаря. Решение о
реализации модели и окончательной панели пользователем не принято.

## Проверки и сохранение этапа

переводчика остаются предложением к обсуждению. Сохранённые идеи пользователя

базы/профилей, скачанных весов, engine jobs или runtime-кэша. Этот документ —
постоянная минимальная таблица фактов и ссылок, а не воспроизводимый dump или
живой второй реестр. Его владелец — readable-rotation handoff.
