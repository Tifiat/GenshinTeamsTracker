## Что работает

| Группа | Пример читаемого текста | Свойства и связь с кодом |
| --- | --- | --- |
| Энергия | Энергия заполнена (Фурина); энергия не меньше 60 | Полная энергия сравнивается с `energymax` того же персонажа; числовые пороги отдельные. Это не синоним готовности ультимейта |
| HP | HP (Фурина) меньше 50% | Процент переводится в `hpratio < 0.5`; абсолютные HP/арифметические выражения сохраняются подробно |
| Готовность | Взрыв стихии готов (Фурина) | Сохраняет `.burst.ready` и проверку `ActionReady`, включая её особенности; не обещает отсутствие блокировки анимации |
| Персонаж на поле | Фурина на поле / вне поля | Булево `.onfield`; проверка другого персонажа не создаёт его активное окно |
| Эффекты | Таймер «…» равен нулю; на таймере осталось время | Личный и глобальный таймеры различаются. Неизвестное имя сохраняется как ключ, не получает придуманного описания |
| Проверенные состояния | Благословение Ночного духа действует; выбран режим Усии/Пневмы | Используются специальные булевы поля персонажа, а не вывод из оставшегося времени статуса |
| Сочетания | Если A и (B или C); если не A | Дерево сочетаний сохраняет группировку. Только полностью распознанное выражение получает простой редактор |
| Повтор по условию | Повторять, пока энергия ещё не заполнена | Условие проверяется до первого выполнения. `while` и `for` без инициализации/шага используют один контракт свойств |
| Созвездия | Число созвездий (Часка) меньше 6 | Число 0–6; применяется в явной границе шаблона особого действия |
| Неизвестная логика | Подробное выражение | Вызовы пользовательских функций, динамические пороги и неподдержанная арифметика сохраняются, не теряют отдельные части при упрощении |

`Condition` — временное значение свойств выбранного блока. `compile_condition`
создаёт обычные узлы общего дерева, `recognize` получает те же свойства из
импорта, `describe` формирует локализованную фразу. Строка Readable никогда
не разбирается обратно в код. `EditorSession.edit_option` меняет условие
того же документа и поддерживает undo. Незаполненные условие/действие остаются
явными слотами и не дают сгенерировать якобы готовую ротацию.

Все новые подписи и пояснения есть в RU/EN/PT-BR. Имена внедряются прежним
resolver; новой базы имён и отдельного хранилища смысловых блоков нет.

## Личные варианты: три разных механизма

Общий реестр `Variant` содержит персонажа, действие, параметр/допустимые
значения, подпись и требования. `VariantChoice` задаёт выбор пользователя;
`plan_variant` выдаёт видимые обычные блоки кода и пояснения.
Общая контекстная панель получает эти варианты для выбранного действия.

| Персонаж | Реализованный вариант | Что создаётся |
| --- | --- | --- |
| Беннет | Навык: нажатие / удержание первого / второго уровня | `skill[hold=0/1/2]`, без проверки режима. Конфликтующий `hold_c4` не удаляется молча: требуется подробная правка |
| Часка | Стрельба в Ночном духе, 6 пуль | Если Благословение не действует — навык; затем отдельная проверка Благословения перед `aim[bullets=6]`. Повторный навык не вставляется безусловно |
| Часка | Та же стрельба, 1–5 пуль | Дополнительная видимая внешняя проверка `cons < 6`. Шаблон явно ограничен C0–C5; для C6 неполная зарядка через этот шаблон не поддержана |
| Фурина | Навык в Усии / Пневме | Если выбран другой режим — заряженная атака, ожидание 2 кадров; затем повторная проверка нужного режима перед навыком |

Есть две явно разные стратегии подготовки, а не скрытый выбор сценария:

- **Подготовить:** создать видимое включение/переключение режима и затем
  проверку перед действием. Это значение `ensure` по умолчанию у API прототипа.
- **Выполнить только при условии:** создать проверку без подготовки
  (`guard`). При ложном условии действие пропускается, ожидание режима не
  подразумевается. Для Фурины этот вариант не содержит заряженной атаки/ожидания.

Выбор варианта для существующего действия — явная правка пользователя через
`apply_variant` / `edit_option`, с сохранением порядка соседних команд,
комментариев и undo. Осмотр импорта, Readable и открытие его свойств не
вставляют навыки, ожидания или условия. Замена одного действия с повтором
больше 1 пока отклоняется: повтор подготовки должен быть отдельным явным
циклом. Дополнительные параметры, которые преобразование не умеет сохранить,
тоже не отбрасываются. Переопределённые обработчики действий/ожидания
блокируют применение зависимых от них шаблонов.

Новый документный контейнер «стрельба Часки» не добавлен. Подготовка — обычные
условия/действия в существующем документе. Дополнительные опции остаются в
общей контекстной панели. Служебная область `{…}` называется «Группа команд»;
её действительная область видимости сохраняется в исходном дереве.

## Найденные ограничения движка

Проверен явно выбранный source
`data/gcsim/engines/engines/gcsim-v2.45.0-20260927011932`; номера ниже относятся
к файлам этого дерева, не к произвольно новой версии. Фразы/шаблоны включаются
только при явно выбранном аудированном профиле `gcsim-v2.45.0-gcsl`.

- `pkg/conditional/character.go:39–58,116–138` — созвездия, энергия, HP,
  onfield, таймеры и делегирование ready персонажу.
- `internal/template/character/ready.go:8–46` — ультимейт проверяет энергию
  и заряд перезарядки, с исключением `IgnoreBurstEnergy`; это не весь путь
  блокировок `pkg/core/player/exec.go`.
- `pkg/core/player/character/mods.go:341–356,386–405` и
  `pkg/modifier/modifier.go:136–144` — активность и оставшееся время различаются.
  У постоянного статуса и на точном кадре истечения таймер может быть нулевым,
  хотя статус активен. Поэтому даже Фавоний подписан как **таймер**, а не
  «эффект уже готов» или «ещё не сработал». Первоначальная такая подпись
  выявлена при независимом review и исправлена до сохранения этапа.
- `internal/characters/chasca/chasca.go:66–82`,
  `internal/template/nightsoul/nightsoul.go:99–126,172–181` — булево состояние
  Благословения. `chasca/skill.go:69–103,120–155` — навык включает/завершает
  его. `chasca/aimed.go:59–78,122–135`, `chasca/cons.go:110–153` — развилка
  обычного/особого aim и обязательные 6 пуль при C6 instant charge.
- `internal/characters/bennett/skill.go:64–79,199–230` — hold и C4 override.
- `internal/characters/furina/furina.go:60–99`, `skill.go:81–132`,
  `charge.go:59–80` — два режима, переключение через charge, изменение режима
  на кадре `CanQueueAfter + 1`. Ожидание 2 кадров и повторная проверка видимы
  в шаблоне; реальное временное исполнение здесь не тестировалось.

**Граница всех предусловий:** они проверяются перед постановкой действия в
очередь. Ожидание анимации, переключения или кулдауна может изменить состояние
до исполнения. Эти блоки не являются доказательством, что особая атака
гарантированно исполнится в нужном режиме. Проверка фактического времени и
диагностика истечения режима требуют отдельной приёмки; автоматическое
исправление произвольной импортированной ротации не реализовано.

Перед интерфейсом остаются решения **для групп редактора**, не отдельные
вопросы о каждой кнопке: как показывать подготовку и ограничения выбранного
варианта; как редактировать вложенные сочетания условий; как показывать
недоступные варианты; как затем отделить статические ограничения от реальных
задержек из проверочного прогона. Текущий API делает условия и подготовку
явными; окончательная компоновка и поведение физических кнопок не утверждены.
Производственные имена, динамические опции новых сборок и реальная панель
ещё не подключены. Данный этап не доказывает полный перевод любого GCSL.
